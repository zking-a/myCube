# 引擎设计与边界

## 实际执行路径

`checkers.js` → 复用的 `checkers_ai_worker.js` → `CheckersAI.chooseMove()` → 棋局阶段 → 预算内搜索。所有对外动作最终再由 `Core.applyMove()` 验证。内部只对刚生成的合法动作进行轻量拷贝应用，不重复生成动画路径。

`Core.chooseAiMove()` / `Core.analyzeAiMoves()` 的兼容入口也转发新引擎。原有存在不完整分数混比问题的 DFS 仅保留在 `baseline/` 供竞技场比较，不留在生产调用路径。

## 阶段判别

每回合依据玩家到其他棋子的最小六边格距离、可达连跳中是否能借用异色棋子、进营数和目标匹配距离判断。不把“第几手”作为开关。两人标准初始局面是 opening；六人初始局面已经相距很近，可能第一手就进入 contact。

opening：Beam 规划，最多 2–3 层自己的发展；每条想象路径遇接触即不再继续假定对手静止；保留对手一步直接获胜警戒。这是节省算力的近似规划，不证明开局彼此完全独立。

contact：双人 Negamax + Alpha-Beta，3–6 人向量效用 MCTS/PUCT。多人不是将其他人合并为一个联盟；选择使用行动者对应的效用分量。rollout 中保留真实席位顺序，每次模拟完成后才回传统计。

endgame：不删除对方棋子。通过一一目标分配距离、相对进度及尾棋评价，并收窄选择性宽度，尝试更深层数。**没有称为“精确残局求解器”，没有提供残局数据库。**

## 预算与可靠性

Alpha-Beta 只有整轮根候选评估完成后才替换当前可靠结果。预算中断丢弃该轮，不将 7 层一部分结果与 3 层完整结果混排。若连第 1 层也未完成，明确返回合法启发式回退，`completedDepth=0, reliable=false`。

所有节点共享单调时钟软截止时间和节点预算。JavaScript 不能在一项同步计算中途精确抢占，因此是软预算，不承诺所有设备严格 400ms。主线程 3 秒 watchdog 可终止挂住的 Worker，并以低成本启发式回退。

搜索是选择性的：根/内部候选有限宽；TT 带深度、行动者、局面及边界标记；搜索局部重复按和棋式效用估算，但 UI 没有新增强制三次重复和棋规则。MCTS 的非终局 softmax 是启发效用，不是校准概率。

## 神经网络使用范围

模型只用于双人红蓝的根节点候选排序；避免为每个深层节点计算昂贵的动作特征。value 另行门槛控制。实验开启只能改变搜索顺序/短名单，不能绕开合法性检查、直接获胜检测和预算回退。

## 竞技场口径

共享随机合法开局，同一开局交换颜色。固定节点比赛用于检验算法；同墙钟软预算比赛另外评估实际吞吐。每盘必须真实达到 10 子进营才算获胜；重复、步数上限或无人可走只计和棋，不按距离给某方判赢。记录逐手动作，可重新验合法性。
